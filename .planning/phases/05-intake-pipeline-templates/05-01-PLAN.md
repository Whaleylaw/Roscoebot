Create `src/projects/template-schema.ts` with:

1. `WorkflowTemplateParamSchema` -- Zod object with fields:
   - `type`: z.enum(["string", "string[]", "boolean", "number"])
   - `description`: z.string().optional()
   - `required`: z.boolean().default(true)
   - `default`: z.unknown().optional()

2. `WorkflowTemplateStepSchema` -- Zod object with fields:
   - `id`: z.string()
   - `title`: z.string()
   - `owner`: z.enum(["agent", "user", "mixed"]).default("agent")
   - `description`: z.string().optional()
   - `capabilities`: z.array(z.string()).default([])
   - `depends_on`: z.array(z.string()).default([])
   - `verification_type`: z.enum(["automatic", "human", "external", "mixed"]).default("automatic")
   - `side_effect_class`: z.enum(["none", "reversible", "irreversible"]).default("none")

3. `WorkflowTemplateFrontmatterSchema` -- Zod object with fields:
   - `name`: z.string() (required -- template identifier)
   - `description`: z.string() (required -- used in LLM matching)
   - `params`: z.record(z.string(), WorkflowTemplateParamSchema).default({})
   - `related_skills`: z.array(z.string()).default([])
   - `related_tools`: z.array(z.string()).default([])
   - `templates`: z.array(z.string()).default([]) (document templates referenced by skills)
   - `triggered_by`: z.array(z.string()).default([])
   - `repeatable`: z.boolean().default(false)
   - `per_item`: z.string().nullable().default(null)
   - `prerequisites`: z.array(z.string()).default([])
   - `steps`: z.array(WorkflowTemplateStepSchema).default([])

4. Export inferred types: `WorkflowTemplateFrontmatter`, `WorkflowTemplateStep`, `WorkflowTemplateParam`

5. `parseTemplateFrontmatter(raw: string, filePath?: string): ParseResult<WorkflowTemplateFrontmatter>` -- follows the same extractYamlBlock + Zod parse + error mapping pattern as `parseWorkflowFrontmatter` in `frontmatter.ts`. Import `extractYamlBlock` from `frontmatter.ts` (or inline if not exported -- check first).

Per D-12: this schema accommodates both rigid/procedural templates (steps with fixed sequence) and structural/flexible templates (steps as guidelines). Per D-16/D-21: synthesized workflows use this same schema.

    depends_on: [implement]

    title: "Manual verification"
    owner: user
    depends_on: [test]
    verification_type: human
