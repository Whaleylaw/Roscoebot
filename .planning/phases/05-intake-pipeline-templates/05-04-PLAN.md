1. Export `INTAKE_SKILL_MD` as a static string containing the full intake skill markdown. The skill content must include these sections:

**## When to Activate**
- When the user describes work to be done, a goal to accomplish, or a task to perform
- Per D-09: no dedicated CLI command -- any agent recognizes work descriptions naturally
- Per D-02: unless the input is unambiguous and clearly a single action, reflect interpretation and get confirmation

**## Clarification Flow**
Per D-11, determine four things through conversation:

Step 1 - Understand the request:
- Reflect your interpretation of what the user wants back to them
- Ask clarifying questions if the scope, approach, or success criteria are unclear
- Per D-02: do not assume -- get confirmation before creating anything

Step 2 - Determine artifact type (D-03):
- Simple single action -> task
- Multi-step structured work -> workflow
- Large initiative with multiple workstreams -> project
- When in doubt, default to workflow

Step 3 - Determine project placement (D-04, D-05, D-06, D-07):
- Read active project summaries (use `readProjectSummaries` + `formatProjectsForPlacement`)
- Use LLM reasoning to assess whether the request belongs in an existing project
- Always propose and ask -- never auto-place (D-05)
- Sub-project creation only when user explicitly requests it (D-06)
- User can override any placement (D-07/PPL-03)

Step 4 - Match or synthesize template (D-12, D-13):
- List available templates (use `listAllTemplates`)
- Present template suggestions with name + description
- If a template matches, collect the template's required params
- If no template matches, mark for synthesis (SYN-01)
- Per D-20: orchestrator will generate workflow from scratch when synthesis is needed

**## Handoff Format**
When clarification is complete, produce a JSON payload for `sessions_send` to the orchestrator:
```json
{
  "type": "orchestrate",
  "goal": "<full goal description>",
  "goalTitle": "<short title>",
  "project": "<project name>",
  "projectDir": "<project directory path>",
  "templateName": "<matched template name or omit>",
  "templateParams": { "<param>": "<value>" },
  "synthesize": true/false,
  "artifactType": "task|workflow|project",
  "constraints": {
    "maxTasks": 10,
    "sideEffectPolicy": "ask-irreversible"
  }
}
```
Include the exact JSON structure with field descriptions inline so agents know the contract.

**## Guidelines**
- Per D-08: the user's agent runs intake, not the orchestrator
- Per D-01: "goal" is just the user's natural language input, not a system entity
- Per D-16/D-21: synthesized workflows will follow the same format as templates
- Per D-22: after a synthesized workflow succeeds, offer to save it as a reusable template
