Create `src/projects/template-resolver.ts` with:

1. `ResolvedTemplate` type:
```typescript
export type ResolvedTemplate = {
  name: string;
  tier: "project" | "global" | "bundled";
  content: string;
  frontmatter: WorkflowTemplateFrontmatter;
};
```

2. `TemplateSummary` type:
```typescript
export type TemplateSummary = {
  name: string;
  description: string;
  tier: "project" | "global" | "bundled";
};
```

3. Internal helper `tryReadTemplate(filePath: string): Promise<{ content: string; frontmatter: WorkflowTemplateFrontmatter } | null>`:
   - Read file with `fs.readFile(filePath, "utf-8")`, catch ENOENT and return null
   - Parse with `parseTemplateFrontmatter(content, filePath)`
   - Return null on parse failure, return `{ content, frontmatter }` on success

4. Internal helper `getGlobalTemplatesDir(): string`:
   - Returns `path.join(os.homedir(), ".openclaw", "templates")`

5. `resolveTemplate(templateName: string, projectDir: string | null): Promise<ResolvedTemplate | null>`:
   - Tier 1 (project-local): if projectDir is not null, try `path.join(projectDir, "templates", `${templateName}.md`)`
   - Tier 2 (global): try `path.join(getGlobalTemplatesDir(), `${templateName}.md`)`
   - Tier 3 (bundled): call `getBundledTemplate(templateName)`, if found parse its content with `parseTemplateFrontmatter`
   - Return first match with tier annotation, or null if none found
   - Per D-13: project-local takes precedence over global over bundled

6. `listAllTemplates(projectDir: string | null): Promise<TemplateSummary[]>`:
   - Collect templates from all three tiers
   - For project-local and global: `fs.readdir()` the templates/ dir, catch ENOENT, parse each .md file's frontmatter for name + description
   - For bundled: call `listBundledTemplates()`
   - Deduplicate: if same name appears in multiple tiers, keep only the highest-precedence one (project > global > bundled)
   - Return sorted by name alphabetically

Import `os` from `node:os`, `fs` from `node:fs/promises`, `path` from `node:path`.

Tests should use `tmp` directories (vitest `beforeEach`/`afterEach` with `fs.mkdtemp`) to create project-local and global template files for testing. Mock `os.homedir()` to point to a temp dir for global template tests.

Create `src/projects/template-save.ts` with:

1. `SaveAsTemplateOpts` type:
```typescript
export type SaveAsTemplateOpts = {
  name: string;
  description: string;
  tier: "project" | "global";
  projectDir: string | null;  // required when tier="project"
  sourceContent: string;      // the synthesized workflow markdown
  overwrite?: boolean;        // default false
};
```

2. `SaveAsTemplateResult` type:
```typescript
export type SaveAsTemplateResult =
  | { ok: true; path: string }
  | { ok: false; error: string };
```

3. `saveAsTemplate(opts: SaveAsTemplateOpts): Promise<SaveAsTemplateResult>`:
   - Validate: if tier="project" and projectDir is null, return `{ ok: false, error: "projectDir required for project-tier template" }`
   - Determine target directory:
     - tier="project": `path.join(projectDir!, "templates")`
     - tier="global": `path.join(os.homedir(), ".openclaw", "templates")`
   - Ensure target directory exists: `fs.mkdir(targetDir, { recursive: true })`
   - Determine target path: `path.join(targetDir, `${opts.name}.md`)`
   - Check for existing file if `!opts.overwrite`: `fs.access(targetPath)` -- if exists, return `{ ok: false, error: "Template already exists: ..." }`
   - Parse source content to extract frontmatter fields (use `parseTemplateFrontmatter` or manual YAML extraction)
   - Build template frontmatter: keep `name` (use opts.name), `description` (use opts.description), preserve `params`, `steps`, `related_skills`, `related_tools`, `templates`, `triggered_by`, `repeatable`, `per_item`, `prerequisites` from source. Strip workflow-instance fields: `id`, `status`, `tasks`, `created`, `updated`, `goal`, `goal_check`, `template`.
   - Validate through `WorkflowTemplateFrontmatterSchema.parse()`
   - Serialize with YAML.stringify + markdown body
   - Write with `writeFileAtomic(targetPath, content)`
   - Return `{ ok: true, path: targetPath }`

Per D-22: This is invoked after a synthesized workflow completes successfully. The agent offers to save and the user confirms.
