## Spacing Scale

Declared values (inherited from existing `projects.css` patterns -- multiples of 4):

| Token | Value | Usage                                                                   |
| ----- | ----- | ----------------------------------------------------------------------- |
| xs    | 4px   | Icon gaps, inline padding, priority stripe width, card-to-badge gaps    |
| sm    | 8px   | Compact element spacing, card gaps, peek field padding, badge padding-x |
| md    | 16px  | Card padding, column gap, widget internal spacing                       |
| lg    | 16px  | Column header padding, board column gap, section padding                |
| xl    | 24px  | Section breaks, empty state padding, dashboard gap                      |
| 2xl   | 48px  | Empty state vertical padding                                            |

Note: `md` and `lg` resolve to the same 16px value but carry distinct semantic meaning -- `md` for internal component spacing (card padding, column gap), `lg` for structural section spacing (column headers, board layout). All values are in the standard set {4, 8, 16, 24, 32, 48, 64}.

Exceptions: Column width fixed at 280px (existing pattern in `.projects-board-column`). No touch-target exceptions needed -- this is a desktop control UI.

## Component Inventory

### New Components (Phase 3)

#### 1. Review Column Header Accent

The Review column on the kanban board uses the same `.projects-board-column` structure but gets a visual accent to draw attention.

```
.projects-board-column--review .projects-board-column__header
```

- Column header gets a 2px bottom border in `--warn` (replacing the default `--border`)
- Column count badge uses `--warn-subtle` background with `--warn` text
- Column name text remains 14px/600 in `--text-strong`

#### 2. Review Card Badge

Tasks in the Review column display a badge indicating review type, following the existing `.projects-board-card__blocked` pattern.

```css
.projects-board-card__review-badge {
  /* Same structure as .projects-board-card__blocked */
  display: inline-flex;
  align-items: center;
  gap: 4px;
  font-size: 12px;
  font-weight: 600;
  color: var(--warn);
  background: var(--warn-subtle);
  padding: 4px 8px;
  border-radius: var(--radius-full);
}
```

Badge labels by verification_type:

- `human`: "Needs Review"
- `external`: "External Check"
- `mixed`: "Auto Passed -- Needs Review"

#### 3. Verification Evidence Section in Peek Panel

Extends the existing `.projects-peek` panel with a verification evidence section.

```
.projects-peek__verification
  .projects-peek__verification-status  (pass/fail/pending banner)
  .projects-peek__verification-checks  (list of check results)
    .projects-peek__check              (individual check row)
      .projects-peek__check-icon       (pass/fail icon)
      .projects-peek__check-type       (file_exists | command)
      .projects-peek__check-detail     (evidence text)
```

- Status banner: 8px padding, full-width, border-radius `--radius-sm`
  - Pass: `--ok-subtle` background, `--ok` text, checkmark icon
  - Fail: `--danger-subtle` background, `--danger` text, X icon
  - Pending: `--warn-subtle` background, `--warn` text, clock icon
- Check rows: 12px font, `--mono` font for command/path values
- Check icon: 12x12 inline SVG, colored by pass/fail state

#### 4. Review Action Buttons

Appear in the peek panel for tasks in the Review queue section. Two buttons side by side.

```
.projects-peek__review-actions
  button.projects-review-btn--approve  "Approve Task"
  button.projects-review-btn--reject   "Reject Task"
```

- Approve button: `--accent` background, `--accent-foreground` text, 12px font-weight 600, 8px 16px padding, `--radius-sm` border-radius
- Reject button: transparent background, 1px solid `--danger` border, `--danger` text, 12px font-weight 600, 8px 16px padding, `--radius-sm` border-radius
- Button container: `display: flex; gap: 8px; margin-top: 16px; padding-top: 16px; border-top: 1px solid var(--border);`
- Hover: Approve gets `--accent-hover` background. Reject gets `--danger-subtle` background.
- No confirmation dialog for Approve. Reject shows inline confirmation (see Destructive Actions below).

#### 5. Review Bar Segment

Already exists: `.projects-bar__segment--review` uses `--warn`. No changes needed. The stacked bar in the dashboard already accounts for a Review segment.

### Modified Components (Phase 3)

#### 1. QueueIndex Type Extension

Add `review: QueueEntry[]` to `QueueIndex` in `ui/src/ui/controllers/projects.ts`.

#### 2. Board Column Rendering

`renderColumn()` in `projects-board.ts` needs to detect when `column.name === "Review"` and apply the `--review` modifier class.

#### 3. Peek Panel Extension

`renderPeekPanel()` needs to include verification evidence and review action buttons when the task has verification data in its checkpoint.

## Destructive Actions

| Action       | Classification                         | Confirmation Approach                                                                                                                                                                   |
| ------------ | -------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Reject Task  | Reversible (task returns to Available) | Inline confirmation replacing button row: "Reject this task? It will return to the Available queue for rework." with "Yes, Reject" (danger style) and "Keep Task" (ghost style) buttons |
| Approve Task | Non-destructive (task moves to Done)   | No confirmation required                                                                                                                                                                |

Reject inline confirmation pattern:

1. User clicks "Reject Task"
2. Button row replaces with confirmation copy + two buttons
3. "Yes, Reject" uses `--danger` background, `--accent-foreground` text
4. "Keep Task" uses transparent background, `--muted` text
5. Clicking "Keep Task" restores original button row
6. No timeout -- stays until user acts

## Interaction Contracts

### Board Drag-and-Drop

Per D-08, users can drag tasks out of the Review column. This follows existing board interaction patterns:

- Drag from Review to Done column: equivalent to Approve (updates queue + checkpoint)
- Drag from Review to Available column: equivalent to Reject (updates queue + checkpoint)
- Drag from Review to Blocked column: moves to Blocked (updates queue)
- No drag INTO Review column -- tasks arrive via verification pipeline only

Note: If drag-and-drop is not yet implemented on the board, the approve/reject buttons in the peek panel are the primary interaction. Drag-and-drop is a stretch goal for this phase.

### Peek Panel Auto-Open

When a task enters the Review column, clicking the card should auto-expand the peek panel showing verification evidence and action buttons. This follows the existing `onTogglePeek` pattern.

### State Transitions

| From State | Action                                   | To State  | UI Update                                            |
| ---------- | ---------------------------------------- | --------- | ---------------------------------------------------- |
| Claimed    | Auto verification passes, type=automatic | Done      | Card moves to Done column                            |
| Claimed    | Auto verification fails                  | Available | Card moves to Available, peek shows failure evidence |
| Claimed    | Type=human or external                   | Review    | Card appears in Review column with badge             |
| Claimed    | Type=mixed, auto passes                  | Review    | Card appears in Review with "Auto Passed" badge      |
| Claimed    | Type=mixed, auto fails                   | Available | Card moves to Available, peek shows failure evidence |
| Review     | User clicks Approve                      | Done      | Card moves to Done column, peek updates              |
| Review     | User clicks Reject (confirmed)           | Available | Card moves to Available column                       |
