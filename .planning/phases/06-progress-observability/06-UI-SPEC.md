## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `var(--bg)` / `var(--card)` | Board background, column background, card background |
| Secondary (30%) | `var(--secondary)` / `var(--border)` | Peek panels, column borders, card borders |
| Accent (10%) | `var(--info)` (#3b82f6) | Workflow badge background (subtle), workflow badge text |
| Destructive | `var(--danger)` (#ef4444) | Not used in Phase 6 (no destructive actions) |

Accent reserved for: **Workflow badge only.** The `[WF-NNN]` badge uses `var(--info)` (blue) to visually distinguish it from the existing red accent (`--accent`), green ok (`--ok`), yellow review badge (`--warn`), and red blocked badge (`--danger`). Blue is the only unused semantic color in the board card badge palette.

## Component Inventory

Phase 6 adds **one new visual element** to the board UI and extends backend surfaces (CLI, RPC, index files) that have no visual component.

### New: Workflow Badge (board card)

**Location:** Inside `.projects-board-card__top` div, after blocked badge and review badge.

**Markup:**
```html
<span class="projects-board-card__workflow-badge">[WF-001]</span>
```

**Conditions:** Render only when `task.workflow` is a non-null, non-empty string.

**CSS class:** `.projects-board-card__workflow-badge`

**Styling contract (exact values):**
```css
.projects-board-card__workflow-badge {
  display: inline-flex;
  align-items: center;
  font-size: 12px;
  font-weight: 600;
  color: var(--info);
  background: rgba(59, 130, 246, 0.1);
  padding: 4px 8px;
  border-radius: var(--radius-full);
  font-family: var(--mono);
  white-space: nowrap;
}
```

**Rationale:** Follows the exact same structure as `.projects-board-card__blocked` (line 556 of projects.css) and `.projects-board-card__review-badge` (line 756). Same font-size, weight, padding, border-radius. Only color differs.

### Badge Rendering Order (within `.projects-board-card__top`)

1. Task ID (always)
2. Blocked badge (if blocked)
3. Review badge (if in review)
4. Workflow badge (if task.workflow is set)

- Project list view, dashboard widgets, navigation, breadcrumbs
- Empty states, error states, skeleton loading

## Interaction Contract

### Board Badge

- **Click:** No special interaction. Badge is inert. Card click behavior (toggle peek) is unchanged.
- **Hover:** No hover state on the badge itself. Card hover still triggers `border-color: var(--text-strong)`.
- **Overflow:** Badge uses `white-space: nowrap`. If card top row overflows, task ID and badges wrap naturally via flexbox `gap: 8px`.

### Status Command

- **Default output (text):** Shows workflows table with active/paused workflows only (D-02). Table renders below active agents section.
- **JSON output (`--json`):** Includes all workflows (including completed/failed) with full task breakdown (D-03).
- **No workflows:** Table section header "Workflows:" still prints. Table body shows "No active workflows" or is omitted entirely (Claude's discretion per existing empty table patterns).

### Live Updates (WebSocket)

- **Trigger:** SyncService emits `workflow:changed` when workflow files change (D-06).
- **Gateway broadcast:** `projects.workflows.changed` message pushed to connected UI clients.
- **Board update:** Board re-fetches on receiving the event, which includes updated `BoardTaskEntry` with `workflow` field. Badge appears/disappears as tasks gain/lose workflow associations.
